## 1. نوع التنفيذ الفعلي والمنصة الحقيقية

المشروع في حالته الراهنة عبارة عن **بنية هجينة ثنائية (Dual/Hybrid Scaffolding)** تتألف من طبقتين:

### أ. بيئة التشغيل النشطة الفعالة (Active Runtime - Web Application)
* **نوع التطبيق**: تطبيق ويب أحادي الصفحة (Single Page Application - SPA) يعمل بتقنية React 19 و TypeScript.
* **المنصة الفعلية**: متصفح ويب عبر خادم Nginx يعمل كوكيل عكسي (Reverse Proxy) على المنفذ الداخلي `8080`، يمرر الطلبات إلى خادم تطوير Vite على المنفذ الداخلي `3000`.
* **الحاوية ونظام التشغيل**: 
  * النظام: Linux 6.6.137+ x86_64 (بيئة معتمدة على Debian/Ubuntu).
  * محرك Node.js: الإصدار `v22.23.2`.
  * مدير الحزم: `npm` الإصدار `10.9.8`.
* **حالة البناء**: تم تنفيذ أمر `npm run build` بنجاح وأنتج حزمة إنتاجية كاملة داخل مجلد `dist/` (حجم ملف JavaScript المترجم: 517.37 kB، وملف CSS: 25.43 kB).
* **حالة الخادم**: يعمل خادم Vite وخادم Nginx بنجاح ويستجيبان للطلبات عبر المنفذ 8080 برمز الاستجابة `HTTP 200 OK`.

### ب. الكود الأندرويدي المصدري غير النشط (Inactive Android Scaffolding)
* **نوع التطبيق المصدري**: تطبيق أندرويد أصلي مكتوب بلغة Kotlin مع واجهات Jetpack Compose وقاعدة بيانات Room محلية.
* **موقع الكود**: مجلد `app/src/main/java/com/example/`.
* **حالة التنفيذ في البيئة**: **متعذر البناء والتشغيل محلياً** في هذه البيئة؛ نظراً لعدم توفر حزمة أدوات تطوير جافا (Java SDK / JDK) أو أداة البناء Gradle في مسار النظام `PATH` (أمر `gradle` يُرجع `sh: 1: gradle: not found`، وأمر `which java` يُرجع `No java`).
* **طبيعة العلاقة بين التطبيقين**: تم تحويل منطق التطبيق ومحتواه النصي من بنية أندرويد Compose المبدئية إلى تطبيق ويب React تفاعلي متوافق مع قيود الحاوية لتوفير معاينة فورية عبر المنفذ 8080.

```
/
├── package.json                         # توصيف اعتماديات الويب وسكربتات التشغيل

│   ├── main.tsx                         # تهيئة تطبيق React
```
